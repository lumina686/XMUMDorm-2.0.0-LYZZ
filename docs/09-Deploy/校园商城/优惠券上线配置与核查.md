## 服务器变量

| 变量 | 配置要求 | 说明 |
| --- | --- | --- |
| NODE_ENV | production | 在实际后端进程生效 |
| DATABASE_URL／MYSQL_URL／RAILWAY_MYSQL_URL | 保留正确的生产连接 | 连接串优先于 DB_*，不要混入本地值 |
| DB_HOST、DB_PORT、DB_USER、DB_PASSWORD、DB_NAME | 无连接串时完整填写 | 必须指向同一个生产库 |
| JWT_SECRET | 保留独立生产密钥 | 不使用内置默认值，不随本次发布轮换 |
| SHOP_COUPONS_ENABLED | 可不配置或 auto；0 显式关闭，1 显式允许 | 自动模式仍要求完整字段与唯一约束；显式 0 不被覆盖 |
| OBJECT_STORAGE_BUCKET | 对象存储方案填写 | 其余端点和凭据沿用原服务配置 |
| PUBLIC_ASSET_BASE_URL | 对象存储方案使用公开 HTTPS 基址 | 需实测上传后能读取 |
| SHOP_ASSET_DIR | 无对象存储时使用绝对路径 | 该路径必须实际挂载持久卷 |
| PORT | 沿用部署平台注入值 | 不改成仅适用本地的固定端口 |

对象存储与持久卷二选一，优先沿用已经工作的方案。
仅填写 SHOP_ASSET_DIR 不代表数据已持久化；多实例必须共享持久目录，或统一使用对象存储。
VITE_API_BASE_URL 若有配置，必须指向现有后端的公开 HTTPS 地址；同源部署可沿用空值与服务器反向代理。
此项在前端构建时生效；修改后仅重启后端不能更新前端产物。

## 发布顺序

1. 确认实际生产数据库名，使用平台备份能力备份，并确认可恢复；在部署平台内操作，不从开发机直连生产库。
2. 在受控任务准备兼容代码；若已有主动设置的 SHOP_COUPONS_ENABLED=0，视为管理员暂停，不擅自覆盖。
3. 在该任务中执行下面的专用 077 迁移，只处理优惠券表和三个订单字段；不要重跑初始化和演示脚本。
4. 检查结构完成后，发布配套 Web 和后端。未配置开关时自动开放，无需新增服务变量；已有显式 0 的环境需维护者决定解除暂停。
5. 在运行环境执行启用后的只读检查，并通过实际站点完成下面的冒烟检查。

下面的库名占位符必须替换成已确认的真实库名；命令不包含密码。
迁移依赖既有 071、072、075 商城结构及用户表。迁移会短暂持有 DDL 锁，安排低流量时执行。

```sh
node scripts/run-migration-077-shop-coupons.js --process-env --confirm-database "实际生产库名" --allow-remote
node scripts/check-shop-coupon-release.js --process-env --production --allow-remote
```

部署自动模式代码后执行（--require-enabled 接受未配置、auto 或 1；仍检查数据库）：

```sh
node scripts/check-shop-coupon-release.js --process-env --production --require-enabled --allow-remote
```

成功标准：进程退出码为 0，databaseChecked=true，schema.ready=true，ready=true。
警告仍需按实际图片上传读取和卷挂载结果处理；检查脚本不会写文件或测试存储上传。
数据库检查只执行 SELECT。迁移命令会创建表和添加可空列，但不删除商品、账号、订单或历史截图。
同一迁移已在独立测试库重复执行通过。

如果服务器采用私有配置文件而非平台变量，可显式传入其受保护文件；不要把文件提交 Git。

```sh
node scripts/check-shop-coupon-release.js --env /secure/server.env --production --require-enabled --allow-remote
node scripts/run-migration-077-shop-coupons.js --env /secure/server.env --confirm-database "实际生产库名" --allow-remote
```

只离线检查文件格式和变量时，可加 --no-database；此时 ready 永远为 false，不能当作上线完成。
`--allow-remote` 是脚本目标保护，不会授予数据库或部署平台权限。

## 站点冒烟检查

- 公共商品目录返回正常，coupons_enabled=true；非营业时段仍不可下单，也不显示付款码。
- 授权商家创建、停用及复制生成下一张；普通学生及其他店铺商家不能访问管理接口。
- 在获准的测试店铺验证固定金额试算，核对订单原价、减免和应付金额；不进行真实转账。
- 确认新券只可占用一次、重复请求不重复创建；取消待处理订单返还次数，确认后不自动返还。
- 商家商品图片与付款码上传后，在学生端可读取；重启服务后仍可读取。
- 付款截图保持私有；学生只能看本人订单，商家只能处理所属店铺订单。
- 验证学生付款提示没有人工核验措辞，也没有把截图上传展示成已到账。

## 停用与回退

将 SHOP_COUPONS_ENABLED 设为 0 并重启后端，会停止新发券与新用券；已有优惠订单仍按快照处理。
保留优惠券与使用记录表、订单字段及兼容的状态处理代码，不回退至不识别优惠订单的旧后端。
不要通过删表或清空核销记录来回退；退款沿用商家现有线下处理方式。
