# T3 无权限入口与服务的双向验证

## 1. Where this task sits

- **Phase 3 社团管理对齐 Web**，目标：社团管理员在 App 上完成邀请成员、设置角色，任何用户都能搜到目标社团。
- 本任务是 **R-2 社团管理邀请与角色设置** 的边界证明：无权限者不见邀请入口，且服务端独立拒绝——任何 App 端隐藏都替代不了服务端校验。
- **Starts after**: T2 角色设置与邀请反馈。**Waits on it**: T4 发现页搜索筛选。

## 2. What the developer needs to know

**Read first**

- `app/src/__tests__/p3a5-club-management.test.tsx` 的「无权限深链」用例 — UI 侧已有 denied 屏断言，补邀请入口不渲染。
- `__tests__/routes/clubs.test.js:304-318` — 删除成员的 403 路由测试样板（本任务的 POST 版照此写）。
- `routes/clubs.js:783-789` — 邀请端点的 `userCanManageClub` 鉴权。

**Settled**

- 双向各一条：UI 不渲染邀请表单（屏幕测试）+ 服务端 403（路由测试）；不加客户端权限预判逻辑。
- 路由测试预期直接绿（端点已有鉴权）；若红即服务端缺陷，停下上报，不在测试里放水。

**Edges and seam**

- 只加测试：管理屏幕测试 + clubs 路由测试；零产品代码预期。

**Run**

- 根目录：`npm test -- __tests__/routes/clubs.test.js`
- `cd app && npm test -- src/__tests__/p3a5-club-management.test.tsx`

**Unknowns**

- 路由测试的鉴权头构造照该文件既有写法（普通成员 token）；没有现成 helper 就停下问。

## 3. The workflow

1. 读上述文件，一句话复述任务。
2. 屏幕侧：denied 屏断言邀请输入与按钮均不渲染。
3. 路由侧：普通成员 POST `/api/clubs/:id/members` → 403。
4. 两侧全绿提交（预期绿；红则按红/绿规则分笔）。
