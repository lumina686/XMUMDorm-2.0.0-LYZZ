# 三模块改进计划：食堂 · 社团 · 万能墙（2026-10-25）

**队列共 6 个阶段，11 项需求，全部来自同日审计文档的 11 份改进计划。** 顺序按风险排：
先修用户看得见的两个严重缺陷（失败反馈、骨架违规），再补缺失能力（社团管理、万能墙删帖），
最后做收拢与硬化（后端去重、状态机收敛）。每个阶段收在一个可演示的证明上。

- 依据：[三模块审计-食堂社团万能墙-2026-10-25](../evaluation/三模块审计-食堂社团万能墙-2026-10-25.md)（缺陷 D-1…D-11 与计划 P-1…P-11）
- 范围：App 端三模块 + 对应后端路由与共享层；不含创建社团站管入口（审计已标注待拍板）
- 任务为单行队列：展开成任务简报交给执行者，本计划不写实现细节

## 2. The approach, requirement by requirement

### R-1 社团失败态可见反馈

- **Approach**: 把三个交互 hook 已经返回的失败态渲染出来——未登录给登录引导，无权限与网络失败给可见提示。
- **Touches**: 社团特性模块、双语词典。
- **Test seam**: 现有社团关注/点赞/报名三套组件测试，不新增缝。
- **Acceptance**: [ ] 未登录点关注出现登录引导　[ ] 网络失败出现可理解文案　[ ] 批次 4 门槛「成功与失败后均有可见反馈」逐项通过。
- **Hard part**: 三处渲染位形态不一，先补行为再做 Phase 6 的收敛，别混在一步。

### R-2 社团管理邀请与角色设置

- **Approach**: 管理页接共享层现成的邀请与角色端点，权限仍由服务端最终裁决。
- **Touches**: 社团特性模块、共享层社团接口。
- **Test seam**: 现有社团管理与路由测试，不新增缝。
- **Acceptance**: [ ] 管理员可在 App 邀请成员并设角色　[ ] 无权限者不见入口且服务端拒绝　[ ] 双语词条齐全。
- **Hard part**: 角色变更的冲突提示，目标成员已是管理员时的反馈。

### R-3 万能墙删除自己的墙帖与评论

- **Approach**: 作者本人的帖与评论挂删除动作，确认后走共享层现成删除端点，列表乐观移除。
- **Touches**: 校园特性模块（万能墙）。
- **Test seam**: 现有墙发布与校园组件测试，不新增缝。
- **Acceptance**: [ ] 仅作者本人可见删除入口　[ ] 删除后列表乐观移除且刷新一致　[ ] 双语词条齐全。
- **Hard part**: 乐观移除与下拉刷新的竞态口径。

### R-4 社团发现页搜索与分类筛选

- **Approach**: 发现页把现成的关键词与分类参数透传给列表接口，输入防抖，翻页状态独立。
- **Touches**: 社团特性模块、双语词典。
- **Test seam**: 现有社团发现组件测试，不新增缝。
- **Acceptance**: [ ] 关键词与分类可组合过滤　[ ] 翻页与筛选状态互不覆盖　[ ] 请求竞争丢弃写法对齐食堂检索。
- **Hard part**: 筛选与滚动加载的状态交织。

### R-5 菜品详情底栏归位骨架页脚槽

- **Approach**: 操作条迁入骨架页脚槽，删掉自绘定位与高度自测量。
- **Touches**: 食堂特性模块（菜品详情）。
- **Test seam**: 现有安全区十清单测试与菜品操作组件测试，不新增缝。
- **Acceptance**: [ ] 键盘弹出/收起高度由页脚槽统一处理　[ ] 机型矩阵抽查无遮挡　[ ] 文件内无自算高度残留。
- **Hard part**: 键盘态下内容区滚动范围变化，别引入双倍留白。

### R-6 社团错误文案具体化

- **Approach**: 按失败类型拆词条（网络/权限/未登录），映射 R-1 的三态反馈渲染位。
- **Touches**: 双语词典、社团特性模块。
- **Test seam**: 现有双语门禁测试，不新增缝。
- **Acceptance**: [ ] 每条错误文案含「错在哪 + 怎么改」　[ ] zh/en 同步　[ ] 三要素逐条自检通过。
- **Hard part**: 与 R-1 共用渲染位，必须排在 R-1 之后。

### R-7 社团按钮 label 收敛

- **Approach**: 帖子/活动行改为标题截断加副文本，删除类按钮只留动作词。
- **Touches**: 社团特性模块。
- **Test seam**: 现有社团详情与管理组件测试，不新增缝。
- **Acceptance**: [ ] 所有按钮 label ≤6 汉字　[ ] 长帖不再撑爆按钮　[ ] 触控目标不小于 48dp。
- **Hard part**: 截断后行内仍可辨识指向哪条帖。

### R-8 后端可选鉴权收拢一处

- **Approach**: 三份手写的可选用户解析收成一份工具，三条路由引用，鉴权行为不变。
- **Touches**: 三条后端路由、后端工具层。
- **Test seam**: 三条路由的既有测试，不新增缝。
- **Acceptance**: [ ] 全库仅一份实现　[ ] 三路由测试全绿　[ ] 无鉴权行为变化。
- **Hard part**: 回调式那份同步化后的行为等价。

### R-9 社团交互状态机收敛一处

- **Approach**: 抽公共交互状态机（六态/epoch/锁），回执校验作参数注入，三个 hook 薄壳化。
- **Touches**: 社团特性模块的三个交互 hook。
- **Test seam**: 现有三套交互组件测试——断言一字不改跑通，即等价的证明。
- **Acceptance**: [ ] 三个 hook 变薄壳　[ ] 现有测试全绿　[ ] 此后新反馈只加一处。
- **Hard part**: epoch 与锁的重置语义必须逐条等价。

### R-10 移除点评缺省评分

- **Approach**: 共享层点评函数删掉缺省评分，漏传即抛参数错误，调用方显式传值。
- **Touches**: 共享层食堂接口。
- **Test seam**: 现有食堂点评契约测试与路由专项测试，不新增缝。
- **Acceptance**: [ ] 漏传评分抛参数错误　[ ] App 与 Web 点评流程回归通过。
- **Hard part**: 找全同源调用方，Web 端共用此层。

### R-11 万能墙清单符号图标化

- **Approach**: 清单模板的文字符号换成两层图标体系内的图标，排版圆点保留。
- **Touches**: 校园特性模块（墙模板）。
- **Test seam**: 现有墙与校园组件测试，不新增缝。
- **Acceptance**: [ ] 模板无模拟控件的文字符号　[ ] 图标归属符合两层规则　[ ] 双语排版无回归。
- **Hard part**: 图标与多行文本的基线对齐。

## 3. Phases

### Phase 1 — 失败看得见（R-1 社团失败态可见反馈，R-6 社团错误文案具体化）

**Goal**: 未登录用户点关注被引导去登录，网络失败时用户看到原因，不再是点了没反应。

**Tasks**

- 打通一条失败链路端到端：未登录点关注弹出登录引导
- 报名与点赞接入同一套失败反馈渲染
- 按失败类型拆分双语词条并补齐中英两侧
- 在三套既有交互组件测试中断言失败态可见
- 社团全量测试回归

**Proof**: 三套交互组件测试通过，真机演示未登录点关注出现引导。
**Not here**: 状态机收敛（Phase 6），食堂与万能墙的错误文案。

### Phase 2 — 底栏归位（R-5 菜品详情底栏归位骨架页脚槽）

**Goal**: 菜品详情的底栏随键盘与安全区正确避让，页面代码不再自己算高度。

**Tasks**

- 操作条迁入骨架页脚槽并跑通整屏
- 删除自绘定位与高度测量代码
- 安全区十清单与机型矩阵抽查回归

**Proof**: 十清单测试通过，键盘弹出/收起无遮挡无双倍留白。
**Not here**: 其他页面的同类底栏迁移。

### Phase 3 — 社团管理对齐 Web（R-2 社团管理邀请与角色设置，R-4 社团发现页搜索与分类筛选）

**Goal**: 社团管理员在 App 上完成邀请成员、设置角色，任何用户都能搜到目标社团。

**Tasks**

- 打通邀请一名成员端到端
- 角色设置接现有成员端点并处理冲突提示
- 无权限入口隐藏与服务端拒绝的双向验证
- 发现页接关键词搜索与分类筛选
- 筛选与翻页互不覆盖的回归验证

**Proof**: 管理测试与发现测试通过，演示邀请成员并按分类搜到社团。
**Not here**: 创建社团站管入口（待所有者拍板）。

### Phase 4 — 万能墙能力收口（R-3 万能墙删除自己的墙帖与评论，R-11 万能墙清单符号图标化）

**Goal**: 作者能删自己的墙帖与评论，模板不再用文字符号模拟控件。

**Tasks**

- 打通删除自己一条墙帖端到端
- 评论删除接入同一确认与刷新口径
- 清单模板符号换成两层图标体系内的图标
- 墙与校园既有测试回归

**Proof**: 墙测试通过，演示删除自己的帖后列表一致刷新。
**Not here**: 管理端删帖（App 不对齐管理后台）。

### Phase 5 — 后端与共享层收拢（R-8 后端可选鉴权收拢一处，R-10 移除点评缺省评分）

**Goal**: 可选鉴权全库只剩一份，点评不再可能编造用户评分。

**Tasks**

- 三份可选用户解析收拢为一份，先让一条路由换用跑通
- 其余两条路由换用并全量回归三路由测试
- 删除点评缺省评分，漏传即抛参数错误
- App 与 Web 点评流程双向回归

**Proof**: 三条路由测试全绿，漏传评分的报错演示。
**Not here**: 鉴权中间件化重构，评分枚举类型化。

### Phase 6 — 社团代码健康硬化（R-9 社团交互状态机收敛一处，R-7 社团按钮 label 收敛）

**Goal**: 三个交互 hook 共享一台状态机，社团页所有按钮文案不再超长。

**Tasks**

- 抽出公共交互状态机，回执校验作参数注入
- 三个 hook 薄壳化，既有断言一字不改跑通
- 帖子/活动行按钮 label 收敛至六个汉字内并核对触控目标

**Proof**: 三套交互测试不改断言全部通过，按钮字数清单达标。
**Not here**: 食堂收藏 hook（结构相近，下一轮评估）。
