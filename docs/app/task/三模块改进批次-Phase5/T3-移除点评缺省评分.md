# T3 移除点评缺省评分

## 1. Where this task sits

- **Phase 5 后端与共享层收拢**，目标：可选鉴权在审计点名的三条路由只剩一份实现，点评不再可能编造评分。
- 本任务把 **R-10 移除点评缺省评分** 落地：`postProductComment` 删 `rating = '人上人'` 缺省，漏传即抛；唯一真实漏传方（Web 回复）显式化。
- **Starts after**: 无（与 T1/T2 独立）。**Waits on it**: T4 全量回归。

## 2. What the developer needs to know

**Read first**

- `shared/api/canteen.js:190-196` — `rating = '人上人'` 缺省本体。
- `frontend/src/pages/FoodDetail.jsx:220-224` — **Web 回复不传 rating**，当前正被缺省值静默注入「人上人」存库（D-10 描述的编造现在真实发生）。
- `routes/canteen.js:319-344,1376-1379` — 后端对回复也强制枚举，但计分 SQL `WHERE (parent_id IS NULL OR parent_id = 0)` 且 `onPrimaryCommentChange` 仅一级触发：**回复的 rating 不计综合分**，只是非空存储字段。
- `app/src/__tests__/p2y-b03-review-form.test.tsx` 与 `p2y-a03-review-contract.test.tsx` — App 缝（表单已显式传值）。

**Settled**

- 共享层：payload 无 `rating` 即抛 `Error`，不再有静默档位。
- Web 回复显式传 `rating: replyingTo.rating`（被回复那条的档位，随 startReply 带入）——回复不计分，引用上下文不产生新评分语义；不用编造的新档位。
- 后端对回复强制枚举的行为本批不动（语义问题记入 open）。

**Edges and seam**

- 改共享层一处 + Web 回复一处；缝：App 点评契约测试 + 两份路由测试（后端零变更应全绿）。

**Run**

- `cd app && npm test -- src/__tests__/p2y-b03-review-form.test.tsx src/__tests__/p2y-a03-review-contract.test.tsx`
- 根目录：`npm test -- __tests__/routes/canteenPermissions.test.js __tests__/routes/canteenWriteGuards.test.js`

**Unknowns**

- Web 端无自动化测试；`replyingTo.rating` 的数据来源（评论列表响应）需在读代码时确认存在，不存在则停下问。

## 3. The workflow

1. 读上述文件，确认评论响应含 `rating` 字段，一句话复述任务。
2. App 契约测试补断言（红）：漏传 rating 时共享函数抛错。
3. 跑红、提交红测试。
4. 删缺省；Web `startReply` 携带被回复评论的 rating 并在提交时显式传入。
5. App 契约 + 表单测试跑绿，提交。
