## 2. What the developer needs to know

**Read first**

- `app/package.json` — test/lint 脚本入口。
- `app/src/__tests__/p2d-01-i18n-gate.test.ts` — 词条齐平门禁在本批次的兜底。
- 改进计划 Phase 1 的 Proof 行 — 本任务的通过标准即那两句话。

**Settled**

- 预期零代码变更；若出现失败，只修可归因于本批次改动的，且红测试与修复分两笔提交。
- 范围 = 社团相关套件（p3-bing-club-*、p3a5-club-*、p3a3-club-*）+ i18n 门禁 + lint + tsc；不跑全仓。

**Edges and seam**

- 不改产品代码；缝就是各套件本身。

**Run**

- `cd app && npm test -- src/__tests__/p3-bing-club-follow.test.tsx src/__tests__/p3-bing-club-like.test.tsx src/__tests__/p3-bing-club-registration.test.tsx src/__tests__/p3-bing-clubs-model.test.ts src/__tests__/p3a5-club-details.test.tsx src/__tests__/p3a5-club-management.test.tsx src/__tests__/p3a5-club-discovery.test.tsx src/__tests__/p3a5-club-notifications.test.ts src/__tests__/p3a3-club-activity-publish.test.ts src/__tests__/p3a3-club-post-publish.test.ts src/__tests__/p2d-01-i18n-gate.test.ts`
- `cd app && npx tsc --noEmit`，然后 `npm run lint`。

**Unknowns**

- 若套件名与实际文件有出入（jest 按模式匹配），以实际文件列表为准调整命令。

## 3. The workflow

1. 跑 Run 中的全量命令。
2. 记录结果（通过数/失败数）。
3. 如全绿：无提交，任务完成；如有失败：定位归因，按规则修复。
