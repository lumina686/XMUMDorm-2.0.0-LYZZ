# T1 未登录点关注弹出登录引导（Phase 1 示踪弹道）

## 1. Where this task sits

- **Phase 1 失败看得见**，目标：未登录用户点关注被引导去登录，网络失败时看到原因。
- 本任务把 **R-1 社团失败态可见反馈** 的第一条链路打通：关注动作的 login 态可见。
- **Starts after**: 无。**Waits on it**: T2 报名与点赞接入同一套反馈。

## 2. What the developer needs to know

**Read first**

- `app/src/features/clubs/ClubScreens.tsx:194-199` — 关注按钮当前只禁用 working 态，login 态无人渲染。
- `app/src/features/campus/CampusScreens.tsx:226-243` — 树洞已定型的登录引导先例（InlineNotice info + 登录按钮 + 跳 /login），照此口径。
- `app/src/features/clubs/useClubFollow.ts:43-67` — login/denied/failed 三态的置位条件。
- `app/src/__tests__/p3a5-club-discovery.test.tsx` — 主页屏幕测试，follow hook 已被 mock，路由 mock 需补 push。

**Settled**

- 登录引导 = InlineNotice（info 色，`action.login` 既有词条，点击 `router.push('/login')`），不新造组件。
- 反馈就地显示在动作旁，不用 Toast；hook 状态机本阶段不改（Phase 6 才收敛）。
- 本任务只引入它自己需要的最小词条（登录提示一条），denied/failed 分型留给 T3。

**Edges and seam**

- 只改社团主页屏幕与双语词典；不动 hook、不动树洞。
- 缝：既有 `p3a5-club-discovery` 屏幕测试，零新增缝。

**Run**

- `cd app && npm test -- src/__tests__/p3a5-club-discovery.test.tsx`
- `cd app && npx tsc --noEmit`，然后 `npm run lint`。

**Unknowns**

- 若 InlineNotice 的 props 与树洞用法有出入，以组件实际签名为准；差异超过 props 级（比如需要新组件）就停下来问。

## 3. The workflow

1. 读上述四处，用一句话复述本任务。
2. 在 discovery 套件加失败用例 1（红）：mock follow.state='login'，断言登录引导可见。
3. 跑测试确认红，提交红测试。
4. 实现：主页渲染 login 态 InlineNotice，词条入 zh/en。
5. 用例 2（红→绿）：denied/failed 至少可见 danger 提示（文案可暂用通用键）。
6. 全套件与 lint 通过后提交实现。
