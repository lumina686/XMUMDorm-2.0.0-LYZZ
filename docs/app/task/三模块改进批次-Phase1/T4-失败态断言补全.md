# T4 三套交互测试断言失败态补全

## 1. Where this task sits

- **Phase 1 失败看得见**，目标：未登录用户点关注被引导去登录，网络失败时看到原因。
- 本任务把 **R-1 社团失败态可见反馈** 的测试矩阵补满：三交互 × 失败三态的 hook 置位断言与 UI 可见断言无缺口。
- **Starts after**: T2 报名点赞失败反馈。**Waits on it**: T5 社团全量回归。

## 2. What the developer needs to know

**Read first**

- `app/src/__tests__/p3-bing-club-follow.test.tsx` — 关注 hook 测试已断言 login/denied/failed 置位，是另两套的对齐样板。
- `app/src/__tests__/p3-bing-club-like.test.tsx` 与 `p3-bing-club-registration.test.tsx` — 盘点各自缺哪个失败态断言。
- T1/T2 的屏幕用例 — UI 可见断言已覆盖的部分不重复补。

**Settled**

- 只补断言，不改产品代码；若断言暴露 hook 置位 bug，停下来按「红测试 + 修复」两笔提交，不算本任务改行为。
- 断言的期望值以 useClubFollow 的既有语义为准（login=未登录或会话失效，denied=处罚，failed=其余）。

**Edges and seam**

- 只动三套 p3-bing hook 测试（必要时补个别屏幕用例）。
- 缝：既有三套 hook 测试，零新增缝。

**Run**

- `cd app && npm test -- src/__tests__/p3-bing-club-follow.test.tsx src/__tests__/p3-bing-club-like.test.tsx src/__tests__/p3-bing-club-registration.test.tsx`
- `cd app && npx tsc --noEmit`，然后 `npm run lint`。

**Unknowns**

- 若 like/registration 的 mock 结构导致某态无法注入（例如构造 401 回执困难），写明缺口与原因，别为凑断言改 hook。

## 3. The workflow

1. 盘点三套测试现状，列出「交互 × 态」缺口表。
2. 一句话复述任务与缺口。
3. 每个缺口先写红/绿断言（置位类断言应直接绿，若红即 bug）。
4. 三套件全绿后提交。

## 4. The test cases

| Case | Input | Expected | Seam |
|---|---|---|---|
| 1 | 点赞时未登录 | state 置 'login'，不发请求 | like hook 测试 |
| 2 | 点赞回执 403 处罚 | state 置 'denied'，不清会话 | like hook 测试 |
| 3 | 报名时未登录 | state 置 'login'，不发请求 | registration hook 测试 |
| 4 | 报名网络错误 | state 置 'failed'，计数不变 | registration hook 测试 |
